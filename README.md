# نظام مكتب النائب المستشار طاهر الخولي

واجهة Next.js عربية RTL لإدارة المكتب عبر الإنترنت. هذه النسخة لا تحتوي على Offline First، وتسجيل الدخول والصلاحيات مؤجلان للمرحلة الأخيرة حسب خطة المشروع.

## التشغيل المحلي
1. ثبّت Node.js 20 أو أحدث.
2. شغّل `npm install`.
3. انسخ `.env.example` إلى `.env.local` وأدخل بيانات مشروع Supabase الحقيقية.
4. شغّل `database/schema.sql` من SQL Editor في Supabase بعد مراجعته.
5. شغّل `npm run dev` ثم افتح `http://localhost:3000`.

## البناء والتحقق
- `npm run build`
- `npm start`

## رفع المشروع إلى GitHub فقط
1. أنشئ مستودعًا جديدًا على GitHub (ويُفضّل أن يكون Private).
2. ارفع ملفات المشروع إلى المستودع، مع عدم رفع `.env.local` أو أي مفاتيح سرية.
3. GitHub هنا لاستضافة الكود فقط؛ التطبيق يحتاج خادم Node.js لتشغيل Next.js، ولن يعمل كتطبيق كامل بمجرد رفعه إلى GitHub.

## تنبيه أمني بالغ الأهمية
النظام Online ويحتاج اتصالًا بالخادم. لا تُدخل بيانات مواطنين حقيقية ولا تفتح الموقع للاستخدام العام قبل تفعيل Supabase Auth وسياسات RLS والصلاحيات. لا تضع مفتاح `service_role` في متغير يبدأ بـ `NEXT_PUBLIC_` أو في كود المتصفح. صفحة سجل الحركات تأسيسية وليست Audit Log موثوقًا حتى ربطها بمستخدمين وصلاحيات.

## الوحدات الموجودة
الرئيسية، طلبات النائب، الخدمات، قاعدة بيانات المواطنين، المستفيدون، الفعاليات، التقارير، نموذج طباعة A4، وسجل الحركات التأسيسي.

## ملاحظات النسخة الحالية
- تمت إضافة إجراءات تعديل وحذف السجلات إلى مدير السجلات، وإضافة رابط صفحة الطباعة A4 إلى القائمة.
- ملف `public/ASSETS-README.txt` يوضح مكان وضع صورة النائب والتوقيع الأصليين؛ لم تكن الصور ضمن الملفات التي وصلت.
- تسجيل الدخول مؤجل حسب طلب المشروع، لكن جداول البيانات مفعّل عليها RLS بلا سياسات سماح. لذلك لن تعمل عمليات القراءة والكتابة عبر المتصفح حتى تجهز المصادقة وسياسات الوصول. هذا مقصود لحماية البيانات، وليس خطأ في الواجهة.
- لم يكتمل التحقق من `npm run build` في بيئة التجهيز بسبب انتهاء مهلة تثبيت الاعتماديات؛ يجب تنفيذ `npm install` ثم `npm run build` محليًا قبل النشر.

## قراءة بطاقة الرقم القومي باستخدام Gemini

تستخدم ميزة OCR واجهة Gemini من جهة الخادم، لذلك لا يظهر مفتاح API داخل كود المتصفح.

1. أنشئ مفتاح API من Google AI Studio: https://aistudio.google.com/apikey
2. أنشئ ملفًا باسم `.env.local` داخل مجلد `taher-office`.
3. أضف السطر التالي مع استبدال القيمة بمفتاحك الحقيقي:
   `GEMINI_API_KEY=YOUR_GEMINI_API_KEY`
4. أعد تشغيل `npm run dev` بعد حفظ الملف.
5. افتح صفحة المستفيدين، ثم ارفع الوش والضهر كلٌّ على حدة. راجع النص والحقول يدويًا قبل النقل والحفظ.

**أمان وخصوصية:** لا تضع المفتاح في متغير يبدأ بـ `NEXT_PUBLIC_` ولا ترسله لأحد. هذه الميزة ترسل صورة البطاقة إلى Google Gemini عبر خادم Next.js؛ لا تستخدم بيانات حقيقية إلا بعد مراجعة شروط خدمة Google وسياسة التعامل مع البيانات وتفعيل تسجيل الدخول وصلاحيات قاعدة البيانات. نتائج OCR احتمالية ويجب التحقق منها يدويًا، خاصة الرقم القومي وتاريخ الميلاد.


## إدارة مخطط Supabase عبر GitHub

- ملف المخطط الأصلي: `database/schema.sql`.
- نسخة Migration لتطبيق المخطط عبر Supabase CLI: `supabase/migrations/20261010150000_initial_schema.sql`.
- لا يتضمن المستودع بيانات مواطنين حقيقية أو نسخة احتياطية من قاعدة البيانات.
- لإرفاق المشروع بمشروع Supabase، ثبّت Supabase CLI ثم نفّذ `supabase login` و`supabase link --project-ref YOUR_PROJECT_REF`.
- لمعاينة التغييرات قبل تطبيقها استخدم `supabase db push --dry-run`، وبعد مراجعة المخطط وسياسات RLS طبّقها باستخدام `supabase db push`.
- لا تنفّذ Migration على قاعدة بيانات تحتوي بيانات مهمة قبل أخذ نسخة احتياطية ومراجعة SQL. سياسات RLS مفعّلة في المخطط، ولا توجد سياسات سماح؛ لذلك الوصول عبر التطبيق سيظل محجوبًا إلى أن تُضبط المصادقة والصلاحيات.
- ارفع ملفات المشروع إلى مستودع GitHub يدويًا أو عبر Git بعد مراجعة `.gitignore`. لا ترفع `.env.local` أو مفاتيح `service_role` أو مفاتيح API.
